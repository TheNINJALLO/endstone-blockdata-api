# BDS 1.26.51 / Endstone 0.11.11

The active compatibility target is now known:

| Setting | Value |
| --- | --- |
| Game version | `1.26.51` |
| Downloaded BDS package | `1.26.51.1` |
| Endstone-reported Minecraft version | `26.51` |
| Selected Endstone SDK | `v0.11.11` |
| SDK commit | `37b395378d91d6d20f1c52bf9d79dbd20e152458` |
| Command-wheel requirement | `endstone>=0.11.11` (no upper bound) |
| Public plugin API | `0.11` |
| Native adapter status | Port and live qualification pending |

Endstone's [v0.11.11 changelog](https://github.com/EndstoneMC/endstone/blob/v0.11.11/CHANGELOG.md)
confirms the game version. Its
[server metadata](https://raw.githubusercontent.com/EndstoneMC/bedrock-server-data/v2/release/1.26.51/metadata.json)
identifies the actual `.1` server package and official download hashes.
Both Windows and Linux archives were downloaded and matched those hashes.
The [target profile](../compatibility/bds-1.26.51.json) also records executable
hashes, the Linux build ID, and hashes of the SDK's generated symbol tables.

The originally supplied `1.26.50.5` archives remain separate historical inputs.
They do not match this target and must not be relabelled as `1.26.51.1`.

## Verify the target

From the project directory in this workspace:

```sh
python scripts/prepare_bds_target.py --archive ../.build-inputs/bedrock-server-linux-1.26.51.1.zip --platform linux-x64 --output build/target-1.26.51-linux.json
python scripts/prepare_bds_target.py --archive ../.build-inputs/bedrock-server-windows-1.26.51.1.zip --platform windows-x64 --output build/target-1.26.51-windows.json
```

The tool selects Endstone `0.11.11` from the profile automatically. Supply
`--endstone-version VERSION` to prepare for a later release. Older versions,
malformed versions, and archives with different bytes are rejected.
Selecting a newer Endstone version does not reuse the `0.11.11` SDK's
qualification: reports distinguish the selected version from the profile's
SDK version and commit.

`server_files_verified: true` means the files match the recorded target.
`native_adapter_qualified: false` means this has not yet produced a qualified
native plugin. `--require-native` returns exit code 2 while this is pending;
verification failures return 1, and successful preparation returns 0.

For historical verification, explicitly select
`--target compatibility/bds-1.26.50.5.json` and the older archive.

## Native work remaining

The SDK version is no longer unknown. The SDK contains changed private Bedrock
layouts and new symbol addresses, so the previous adapters still need porting.
Existing native builds retain their original exact BDS/Endstone guards.

The remaining steps are to port the native adapters, build against the selected
SDK and runtime Python/pybind11 ABI, and run native load, gameplay, persistence,
and shutdown tests. No updated DLL/SO has been produced by this target change.
The open-ended wheel dependency expresses installation eligibility; it does
not promise identical native layouts in later Endstone releases.

Python bridge interpreter constraints and previous published release versions
remain unchanged. Historical binaries continue to target their original
server/Endstone pair.
